## What

A caller makes ONE request that takes the fenced lock, applies several changes across maps, and
commits: all applied or all rejected. One redo entry or a commit marker so a restore never applies
half. Built on both the server side and the generated client side so the lock, fence token, retry
and commit are hidden from the user; the API is generated by tacplus, the implementation is
Stratum's. The identity graph adds a unique index on mapping keys (conditional write), a revision
per record and a change feed.

## Shape (huddle Jody + hub, 2026-10-31)

- **`Apply` is the transaction.** One request, ops across **several record types (maps)**, all or nothing. Locks belong to the
  store and are taken in canonical order (type name, then key). No caller ever holds a lock between calls. It shipped in
  tacplus 2.5 (#163). This item finishes it.
- **One home site per transaction.** Every entity an `Apply` touches has the same home (primary) site. It runs there under that
  site's fence term. Jody: transactions won't span home sites. Cross-site `Apply` is refused (tacplus-dev/stratum#22).
- **Reads are a converged view, not a snapshot** (Jody): "they do not have to have a atomic consistent view. The reality of the
  situation is that the view is effectively converged. Anything that they would try to do on that view would require them to,
  of course, check again once they had the lock, and then they might choose to abort." So:
  - no cross-map snapshot reads; `Get` is consistent per entry, as today;
  - **validation happens under the locks, inside `Apply`:** every op can carry a condition (the revision it read). An entity the
    transaction **depends on but doesn't write** needs an **`AssertUnchanged`** op that takes its lock and checks its revision
    without writing. Any failed condition aborts the whole `Apply` (`FAILED_PRECONDITION`, naming the op), and the caller
    re-reads and retries or gives up.
- **Still to build:**
  - one **redo record** (or a commit marker) per `Apply`, so a restore never applies half;
  - a **transaction id** on every change event an `Apply` produces, so a consumer watching several maps can group them;
  - **`AssertUnchanged`**.
- **Generated on both sides:** retry-on-abort helpers in the generated client. User code writes "read, decide, `Apply` with
  conditions" and never sees locks or fence tokens.
