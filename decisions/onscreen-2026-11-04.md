# OnScreen: a wall display of everything going on (Jody, 2026-11-04)

Jody, 2026-11-04 (huddle): "I need a way to see what is going on across everything. I need a Swift app that will run
full screen in one of my Desktop monitors. It should show me what is going on, what is waiting on what, issues,
pending, running, etc. Its something I will not normally need to interact with I can just look at it and maybe drill
down into. It should run on our tacplus platform."

Answers: running on the platform it watches is fine ("a compiler that is written in the language it builds does. its
just a bootstrap process"); open source; "The desktop app needs to connect to the backend service only. polling is
fine between the backend service and GitHub/GitLab"; the name is **OnScreen**.

## Decided
- **github.com/tacplus-dev/onscreen**, open source: a tacplus project with two parts.
  - **The backend, a tacplus service in Rust,** deployed in the cluster like any other. It polls GitHub (tacplus-dev's
    issues, PRs, labels, Blocked-by, looper comments, releases) and GitLab (pipelines and jobs: running, pending and
    what each waits for), and reads the cluster (nodes, pods, deployments) read-only. It builds one model, including a
    **dependency graph** of what waits on what (Blocked-by, needs-decision, waiting on Jody, jobs waiting for a node or
    a slot, managers' merge queues), keeps it in kernel state, and serves it through a generated **Watch** stream.
    Credentials are the platform's: the GitHub App through KMS and Workload Identity, a read-only GitLab token from
    Secret Manager by version, a read-only Kubernetes role. Read only, everywhere.
  - **The Mac app, SwiftUI,** on the generated tacplus Swift client. **It connects to the backend only**, through the
    gateway, signed in with Google OIDC (`jody@seabeam.net`; we are not an IdP); only allowed principals read.
    Full screen on a chosen display, read-only, live from the Watch stream, "stale since" when the stream stops.
    Panels: Waiting on Jody (first), Running, Pending and what each waits for, Recently closed and released,
    Security. Click to drill down into an item and its chain of waits; a second click opens it on GitHub or GitLab.
- **Polling** between the backend and GitHub/GitLab, about once a minute within their rate limits; webhooks later.
