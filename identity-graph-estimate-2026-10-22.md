# Identity graph: code survey and work estimate (2026-10-22)

Survey agent report for Jody's question: how much work would the huddle's SPIFFE/XID changes take, and what is already in progress. Companion to `identity-graph-huddle-2026-10-21.md`.

## Survey

**1. SPIFFE layout today.** The grammar has one source in tacplus, `pkg/internal/common/spiffe/grammar.go` (segment pattern, reserved tags), hand-ported into five chassis templates: `pkg/templates/{go,java,rust,python,typescript}/chassis/spiffe/`. Roots are `/system/<loc>/services/<svc>`, `/tenants/<t>[/workspaces/..]`, `/people/<pid>/users/<pid>`; typed leaves are `users`, `clients`, `credentials/<kind>/<id>`, `data/<kind>/<id>`, `workloads` (`Spiffe.java.tmpl:13-20, 54-67`; Go `classifyPerson` at `spiffe.go.tmpl:514`). Shared vectors: `cross-test/fixtures/spiffe_vectors.json` (160 lines); `pkg/internal/common/spiffe/people_tenant_test.go:19` pins the `people` carve-out in every port. Token claims: `sub` is the relative stable id, `sub_type` user|service|pipeline, `namespace`, `linked` (`pkg/proto/sys/token.proto:31,41,58,67,156-160`); `Azp` = kernel|oauth|cloud-auth (`spec.proto:299-313`). Kernel stamps the namespace from the minting delegate's `tenant_namespace`, never OPA, via `Spiffe.userSpiffeId(trustDomainReader.get(), ns, id)` (`IdentityServiceImpl.java:603, 775, 819`); trust domain is a Supplier injected at `:358`.

**3. Device principals.** `CreatePersonalPrincipal` + `AUTH_BROKER_KIND_DEVICE` mint are implemented (`IdentityServiceImpl.java:5034, 768`; `DevicePrincipalTest`, 601 lines); personalauth exposes `CreateDevicePrincipal`/`MintDeviceTokens` (`personalauth.proto:99,110`); WebAuthn device side of a link (`DeviceWebauthnLinkTest`, 923 lines). `PersonalCredential.platform_synced` exists (`kernel.proto:1355`). **No attestation code** (App Attest/Play Integrity: grep empty; proto says "named as follow-ons, not stubbed"). **4. Tenant identity.** `Tenant.name` is the key and the SPIFFE segment (`kernel.proto:1968-1976, 2278-2282`); `TenantConfigEntry.tenant_name`. **No opaque tenant id exists.** IdP binding: `tenants/<t>/oauth.yaml` → operator `LoadTenantIdps`/`tenantNamespaceRego` (`opa.go:56,146,262`) → `namespace.rego`. Name-in-path dependents: `tenant_namespace` 26× in `kernel.proto`, 35× across protos; gateway 16 refs in 4 files (`resolver.rs`, `proxy_grpc.rs`, …); operator 39 refs; kernel chroot in 5 files.

**5. XID.** Nothing named xid/external_id. The closest thing is `PersonalPrincipal.principal_id`: "kernel-minted and opaque. Deliberately NOT derived from any key" (`kernel.proto:1392-1397`) — that is the XID, under the wrong root. `Person.user_id` is the opposite (derived from provider+sub). **No looper is working on XID, memberships or D29 membership**; schematic looper is on sign-in domains; `loopers/STATE.md` has no identity item; `RESUME.md:639` shows D29 "dispatched" 10-02, only SAML removal and Microsoft-in-oauth landed.

**6. Stratum.** Kernel has no Stratum client (grep empty). Durability is `IdentitySnapshot` (one atomic `KernelDiskState` on the kernel volume: principals, people, tenants, grants; `IdentitySnapshot.java:17-43`) plus Hazelcast. Uniqueness today is a node-local `synchronized` (`IdentityServiceImpl.java:821`). Stratum `design.md:121-129` records the huddle; transactions/unique index/change feed are the post-launch item (`mvp-plan:793-798`); domain-level Stratum is not in the quorum equation.

## Minimal path

(a)+(b)+(e)+(j), with (c) reduced to "memberships on the XID row + one upsert RPC", built by treating `PersonalPrincipal` as the XID row: move its root, add `mappings`, make `mintPersonToken` resolve a mapping instead of deriving `user_id`, and the existing exchange is the per-tenant token. **About 3–4 weeks** of looper work plus one coordinated all-service roll. Deferred: TID (store it, don't path it), Stratum, merge, attestation, name mappings.

**Tradeoffs.**
- *Launch (12-01).* The launch sign-in works today through the `namespace.rego` stopgap, and the looper is actively investing in that shape (domain matchers, post-auth mapping). The minimal path replaces it; done mid-stream it halts that work and forces a full-fleet roll with every in-flight user token invalid. Done after launch, the rego and domain-record work is thrown away.
- *Cheaper now.* The user `sub`: records owned by `spiffe_id` (`spec.record owner`, `spec.proto:466, 694`) will carry user subs; rewriting those after customers exist is a data migration, before it is a regen. Same for `Person.user_id` derived ids: zero real rows today.
- *Pure risk.* (h) and (d): a domain-level Stratum with transactions that nobody has quorum-modelled, and a tenant rename that touches gateway routing, operator deployments and chroot keys at once. Neither is needed for one XID per mapping key inside one cluster; the kernel's node-local lock plus `IdentitySnapshot` holds that invariant today and the huddle's own §21 says the quorum question is answered before (h) is built.
