Suggestion: A new repository gets main's ruleset the day it is created: admiral, skipper and fleetbox have none, so a report's token can push to their main past the gates
Type: Security
Summary: admiral and skipper (created 2026-11-19T21:47Z) and fleetbox (2026-11-22T22:39Z) have no ruleset on main (GET /repos/tacplus-dev/<repo>/rulesets answers [] for all three, read 2026-11-24), while every repository that existed on 2026-11-04 carries 'main: only the manager (looper#83)' (coop, looper, tacplus, onscreen, chaos, people, website, registry checked). looper-ruleset apply is Jody's by-hand step, 'run it again whenever a repository is added', and nothing runs looper-ruleset check since: so in three public repositories a report's token, the one a model holds, can push to main or write it through the contents API, and their managers have merged about 20 lands there since 2026-11-20 (admiral #5 to #8, skipper #3, #7, #8, fleetbox #4, #7) as if the floor held. None of the three has a .github directory either, so no gates workflow runs on a push there. Apply the ruleset to the three now (looper-ruleset apply admiral skipper fleetbox, then looper-ruleset probe on one with a report's token), and make the check automatic: planning-files-check or each repository's nightly scan runs looper-ruleset check, files a missing or drifted ruleset as a bug for the hub, and the kicker starts no report in a public repository whose main has none ('ruleset first', as looper#73's onboarding rule says 'pin it first')
Why: Security first: 'nothing reaches main without green gates' (decisions/looper-job-per-issue-2026-11-03.md; the accepted suggestion of 2026-11-04, looper#83) is the floor every other control rests on, and it is missing exactly where new code lands fastest, three weeks after it was applied to the 28 repositories of that day. It is the same day-one hole the open suggestion of 2026-11-23 names for fleetbox's build.lock: a repository is created and the loopers work in it before the hub's onboarding steps run. Also Operability: a by-hand step in a README with no check behind it drifts, and the check already exists
