Suggestion: Pin every repository, so the build pipeline and its security checks run anywhere
Type: Security
Summary: The deterministic security floor (#49) and credential-less gates (#71) run only in tacplus-dev/build, only for a pinned repository, and only looper is pinned: tacplus-dev/build ran 0 jobs last night. Have the hub file the pin issue per repository it promised on #71, set BUILD_TRIGGER_TOKEN and the nightly schedules by pipeline, and add both to looper#84's Blocked-by
Why: looper's ROADMAP lists #49 (SCA and SAST on every build, fail on HIGH/CRITICAL) as done, but it reaches no service. A build of a repository with no tacplus.lock or build.lock is a fail verdict (README, Build pipeline: 'No pin ... is a fail verdict, never a guess'), and a checked GitHub contents call on 2026-11-06 found a pin in 1 of the org's 31 repositories (looper's build.lock). So the nightly security schedules would fail at plan everywhere else, and every manager still runs report code in its own job. Since #90 that is the verdict job, where a test can forge the verdict (looper PROPOSALS, 'The verdict a test can write'). The nightly agent scans in coop, eventbus and llmproxy have each proposed a per-repository security workflow of their own because no build report exists to read. That duplicates #49 rather than switching it on. The same pins gate the speed-up Jody is waiting for: looper#84 (pods instead of the runner VMs that left 112 issues waiting 131.06 h for a VM last night) needs 'BUILD_TRIGGER_TOKEN and every repo pinned' (its own body). Yet its Blocked-by names only cluster#6 (closed) and tacplus#315, so once #315 closes it is taken as ready, and the pins it needs have no issue to wait on. Also serves Performance and Correctness (the roadmap's 'done' becomes true).
