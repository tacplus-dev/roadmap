Suggestion: A service release is what the manager tagged on green main: a v* tag ruleset in every repository, one release workflow pinned by commit that attests what it publishes
Type: Security
Summary: A pushed vX.Y.Z tag publishes ghcr.io/tacplus-dev/<service>:X.Y.Z with the workflow's own GITHUB_TOKEN, and every report's token (contents: write) can push a tag: main's ruleset names no tag (looper's PROPOSALS), which pigeon's and coop's PROPOSALS of 2026-11-15 both call out ('Anyone who can push a tag can publish an image'). The release workflows are copied per service and diverging (doppelganger's PROPOSALS), pin their actions by mutable tag (kernel's, llmproxy's, pigeon's and tenantecho's actions/checkout@v4; llmproxy#56 is needs-decision on it; coop's alone pins by commit), and none but opa's and the looper image's attests provenance. Give each repository a refs/tags/v* ruleset (create and update by the tacplus-manager app and Jody only), one reusable release workflow in looper pinned by commit with attest-build-provenance as image.yml has, and have the fleet lock verify the attestation
Why: Bar A releases eleven services this way in the coming days (kernel#7 and opa#2 are done; gateway#6, oauth#5 and eventbus#2 got looper:workflows last night), and tacplus fleet build locks to whatever digest a tag push published. The accepted suggestions closed main (2026-11-04) and the looper image (2026-11-09); the services' tags are the gap left: a report whose issue text came from outside the org (looper#40) could tag a release of its own branch, and a repointed actions/checkout@v4 runs in every release job with packages: write. Also serves Operability (one workflow kept in one place instead of eleven copies, the line-tag and Latest rules with it) and Developer experience

## Cost
The hub: a tag ruleset per public repository (refs/tags/v*: creation and update restricted to the tacplus-manager app and Jody, no deletion), minutes each, as looper-ruleset did for main in 28 repositories (one more rule in it). A looper day in tacplus-dev/looper: a reusable release workflow (workflow_call; actions pinned by commit with the version in a comment; SOURCE_DATE_EPOCH from the tag; attest-build-provenance on the pushed digest), and each service's release.yml becomes a 'uses: tacplus-dev/looper/.github/workflows/release.yml@<sha>' with its inputs (a report needs looper:workflows per repository, as gateway#6, oauth#5 and eventbus#2 now have). Hours in tacplus: fleet build verifies 'gh attestation verify --source-ref refs/tags/vX.Y.Z' before it locks a digest. No money

## Reuse considered
GitHub rulesets already guard main in the 28 repositories (looper-ruleset apply; the same mechanism takes refs/tags/*); image.yml's attest step and the plan's gh attestation verify are the pattern; coop's release.yml is already pinned by commit; planning-files.yml is already a reusable workflow every repository calls. Considered: releases from the GitLab build pipeline now (looper#17: it needs a ghcr push credential GitHub offers only as a classic personal token, the addendum's reason to wait); Dependabot for the pins (keeps them moving once pinned; no substitute for the ruleset); each repository fixing its own copy (eleven times, and they drift again)
