Suggestion: The tacplus-manager app holds workflows: write, so a workflow fix the hub approved lands through the train instead of waiting days for a hand
Type: Security
Summary: Since looper#194 (2026-11-19) a land that changes .github/workflows/ is sent back needs-decision for a person, because the tacplus-manager App lacks the workflows permission: Jody's step, asked for since looper#112 (2026-11-09; looper-token mints the manager's token with it only once LOOPER_MANAGER_WORKFLOWS=write is set). What waits is exactly what GitHub Actions security is about: tacplus#584 (HIGH semgrep run-shell-injection in images.yml, the workflow that publishes every tacplus image; its fix and seven backport PRs ready since 2026-11-13 10:47Z; pulled out of the merge train 2026-11-18 23:04Z, 'held for the hub to land by hand'), tacplus#337 (the same, open since 2026-11-06), llmproxy#56 (release.yml's actions pinned by mutable tag with packages: write; its SHA pins wait on a looper:workflows label no member set in nine days), coop#14 and kernel#22 (release.yml's launcher steps 'a person removes'), fleet-dev#25 (the action SHA pins). Grant the app Workflows read and write, set LOOPER_MANAGER_WORKFLOWS=write, and have the manager stage a looper:workflows land in a batch of its own (looper#194's other option), so the manager's push carries the permission only for an issue someone with write access marked
Why: The merge train is live for tacplus since 2026-11-18 22:52Z and its first candidate of 40 went red in seconds on these two lands; now they are held for a hand, and every release workflow change of bar A (the open 2026-11-16 suggestion: one release workflow pinned by commit in each repository) would queue the same way. A HIGH injection finding with its fix attached has waited six days for a person, which is the opposite of 'merging fixes first' (throughput-first, 2026-11-11). The manager runs no repository code (the 2026-11-05 decision), so the permission sits where the 2026-11-09 decision put a report's: with a label a person set. Also serves Performance (no bisect, no hand landing) and Operability
