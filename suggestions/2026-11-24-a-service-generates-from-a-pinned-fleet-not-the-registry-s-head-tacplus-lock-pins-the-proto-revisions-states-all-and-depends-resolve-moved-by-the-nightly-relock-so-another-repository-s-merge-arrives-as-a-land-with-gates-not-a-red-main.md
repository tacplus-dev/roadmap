Suggestion: A service generates from a pinned fleet, not the registry's HEAD: tacplus.lock pins the proto revisions states: all and depends resolve, moved by the nightly relock, so another repository's merge arrives as a land with gates, not a red main
Type: Correctness
Summary: tacplus.yaml's states: all and depends: resolve other services' protos through tacplus-dev/registry when a build runs, and tacplus.lock pins the compiler and build image only (eventbus's: 'tacplus: 2.6.1' and 'build_image: ...@sha256:...'). On 2026-11-20 kernel#69 added TenantRegistryEntry and eventbus's main went red with no eventbus commit (eventbus#37, 2026-11-22: 'No eventbus code changed: the last non-scan commit on main is 2f3ce13 (#26), and the gates passed before that change upstream'). eventbus's PROPOSALS (2026-11-22) asks tacplus for the fix: 'Pinning the fleet's revisions in a lock (written by a command like tacplus pin, moved by a commit the looper's relock opens, as with the image) would make a fleet change arrive as a reviewable PR whose gates run before it lands, per decisions/deterministic-builds-2026-10-27.md. This is tacplus behaviour, so it would be a tacplus-dev/tacplus feature that eventbus adopts.' No tacplus issue holds it. Have tacplus pin write the registry revision (or each dependency's commit) it resolved into tacplus.lock, tacplus generate read it instead of the registry's HEAD, and looper#226's nightly maintenance move it with a land per repository, so a contract change lands in each consumer through its own gates
Why: Correctness, by the deterministic-builds decision: a build whose inputs are another repository's HEAD is not reproducible, and today a merge in kernel can turn eventbus, gateway, every states: all consumer and the fleets' clients red at once with nothing to bisect in the red repository; a red main then stops every land there (looper#180 compares with main's findings, and the gates are red regardless), as fleet-seatrials' night showed for a different cause. Also Security (supply chain: an unpinned input fetched at build time from a repository with its own writers) and Performance (no red-main round trips for a change no one in the repository made)
